# 按会话模仿聊天风格

为不同私聊或群聊指定不同的风格文档。插件启动时加载已启用配置，收到新消息后判断是否需要回应，需要时按字数延迟发送，不需要时保持沉默。

## 配置位置

以下路径均相对于 Mirai 为本插件分配的数据目录。首次启动后会生成示例文件和默认文档：

```text
person.properties                         共用的账号、AI 接口配置
person/
  my-chat-style-system-prompt.md           原有的默认群聊风格文档
  profiles/
    private.properties.example            示例，不会启用
    friend-a.properties                   自定义私聊配置
    group-a.properties                    自定义群聊配置
```

在 `person.properties` 中保留现有 AI 配置：

```properties
bot.id=当前实际登录的QQ号
bot.name=本人昵称
ai.url=https://api.deepseek.com
ai.model=deepseek-flash
ai.key=现有API密钥
ai.thinking.enabled=false
```

`bot.id` 用来识别本人、@ 本人和引用本人，必须填写实际发信账号。风格文档不会改变发送消息的 QQ 账号。`ai.thinking.enabled` 可以留空，此时不向接口传递思考开关。

## 添加会话

将示例复制为 `friend-a.properties`，填写：

```properties
enabled=true
target.type=private
target.id=对方QQ号
prompt.file=private-style.md

history.size=80
debounce.ms=2500
group.max.wait.ms=10000

send.base.delay.ms=600
send.char.delay.ms=180
send.max.delay.ms=8000
```

把 UTF-8 风格文档放到 `person/private-style.md`。`prompt.file` 的相对路径以 `person/` 为基准，不是以 `profiles/` 为基准；也可直接填写绝对路径。本次生成的私聊文档可以这样使用：

```properties
prompt.file=/home/xiaozhangup/文档/QQChatExporter/说话风格_984177828_私聊版.md
```

群聊另建一个 `.properties` 文件，将 `target.type` 改为 `group`，`target.id` 填群号，按需要指定另一份文档。可添加多组，不需要执行聊天指令来开启。

修改配置或文档后重启插件生效。设置 `enabled=false` 或移走对应 `.properties` 文件，重启后停用。默认示例不会自动启用任何会话。

同一类型、同一目标出现多个启用配置时，这些重复配置均不启用，日志会列出文件名。文档不存在、为空或参数无效时，只跳过对应配置；共用的账号或 API 密钥缺失时，整个聊天模块不启动。其他模块不受配置错误影响。

## 发言与发送规则

模块使用一次模型调用，结合风格文档与近期上下文，完成是否发言及回复生成。风格文档负责语气，模块规则优先规定静默与分条协议：

- 不发言：模型仅返回 `<empty>`，不会发送给聊天对象。
- 单条：模型直接返回正文。
- 连发：模型返回 `第一条<spilt>第二条`。分隔符不带反斜杠，拼写固定为 `spilt`。
- 模型意外返回换行时，实际换行（LF、CRLF、CR）也会作为分条边界，空白段忽略，各条仍按字数延迟发送。
- `<empty>` 混入正文或分隔符带反斜杠属于协议错误，本轮停止发送并记录日志。

私聊的提问、后续讨论和有回应价值的分享可以接话；“收到”“好”等结束语不要求回复。群聊结合 @、引用发送者和最近参与的话题判断，其他人互聊、重复通知和无关刷屏默认不插嘴。没有 @ 也允许适时参与，拿不准时倾向沉默。最终判断由配置的模型完成，实际表现需用真实对话观察。

所有有效目标消息都会进入上下文，沉默不会清空历史。自己的消息和以 `/` 开头的指令不会触发此模块。上下文包含发送者账号、名字、收到时间、消息 ID、@ 和引用信息，以及本轮新增消息标记；本人输出只有得到平台发送确认后才进入历史。

每次模型返回的决定也会进入独立的 `decisions` 上下文，包括 `<empty>`。记录包含原始回复、处理到的消息序号、时间、已确认发送条数及结果：`silent`（静默）、`sent`（已全部发送）、`interrupted`（被打断）、`superseded`（被新消息取代）、`failed`（解析或发送失败）。记录实际返回的决定，不请求或保存模型的内部推理。模型看到的实际聊天记录与决策记录分开，未发出的内容不会伪装成已发消息。

每组会话独立维护内存历史、合并窗口与发送流程，群号和 QQ 号即使相同也不会混用上下文。`history.size` 分别限制最近的顶层消息数和决策数，包括本人已发消息。重启后历史清空，不会加载旧导出记录、补发旧回复或主动找人聊天。

## 等待与打断

收到消息后等待 `debounce.ms`，期间收到新消息会重新计时，合并后交给模型。群聊每批最多等待 `group.max.wait.ms`；它限制消息合并时长，不保证模型生成期间持续有新消息时仍然插话。

每条消息，包括第一条，发送前等待：

```text
min(send.max.delay.ms,
    send.base.delay.ms + 本条字符数 × send.char.delay.ms)
```

默认 10 个字符等待约 2.4 秒，最长 8 秒。字符数按 Unicode 码点计算，通常一个中文字符算一个；组合 emoji 可能由多个码点组成。下一条在上一条确认发送后开始等待，模型请求耗时和 QQ 发送耗时另外计算。

新消息到来时：

1. 正在生成：当前请求结束后丢弃旧结果，合并新消息重新判断。同一会话不会并发生成多个回复。
2. 正在等待发送：立即放弃尚未发送的部分，重新合并消息。
3. 已有部分发出：已发部分保留在历史中，剩余部分取消，重新判断。

已经提交给 QQ 平台的一条消息不能保证取消，程序等待该条回执，不自动撤回。发送失败或结果不确定时不自动重试，也不会把内部错误发给聊天对象。API 连接超时为 10 秒，读取超时为 60 秒。

插件停用时取消各会话处理和待发送消息；已经提交平台的那一条仍等待回执。

参数范围：`history.size` 为 1–10000；毫秒参数为 0–300000，其中 `group.max.wait.ms` 至少为 1。群聊的最长合并等待不能小于 `debounce.ms`，最大发送延迟不能小于基础延迟。

## 旧配置迁移

首次升级时，如果 `person/profiles/` 中没有 `.properties` 会话文件，会将旧 `enabled.groups`、`enabled.users` 转为 `legacy-group-群号.properties` 和 `legacy-private-QQ号.properties`，继续使用原来的默认风格文档，并保留旧历史条数、合并等待和每字延迟。

迁移后以独立配置文件为准。`person/.profiles-migrated` 防止以后删除配置又被旧白名单自动恢复。如果首次升级时已有新配置，则直接使用新配置，不再迁移旧白名单。旧 `group.max.batch` 不再使用，改为按最长等待时间合并。

注意新版第一条也会延迟，后续延迟按当前待发消息长度计算，和旧版第一条立即发送、按上一条长度等待的行为不同。

## 查看状态

启动日志会显示加载的会话数、跳过的配置和重复目标。运行日志只记录会话配置名、静默或计划发送条数、token 用量及处理错误，不主动打印整段聊天或模型回复。

图片使用 `deepseek-flash` 的原生视觉能力，通过 `image_url` 内容块传入 QQ 提供的图片链接，不再运行本地 OCR 或 Python 脚本，旧 `ocr.*` 参数不再使用。普通消息、引用消息和合并转发中的图片都会随相应文字传入，图片标签保留它们在上下文中的位置。历史中的图片链接随消息一起保留，超出历史条数后移除；链接需要可被模型服务访问。

图片支持 JPEG、PNG、GIF、WebP；模型接口的数量、大小等限制见 [DeepSeek 图像理解文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)。图片中文字作为聊天数据理解，不能覆盖模块规则。

当前消息事件入口主要接收他人的消息，不提供检测本人在其他客户端手动发言并自动暂停代聊的功能。
